3 日目 — 実世界 PDF 1008 件による検証

「どんな PDF なら安全に sumi へ渡せるか」を、実物の PDF を大量に変換して確かめる作業です。 手で選んだ数件ではなく、実世界の分布に近いものを集めて自動で測ります。

集めかた

Wikimedia Commons から 20 の検索軸（請求書、報告書、プレゼン、地図、論文、図表など）で 約 55 件ずつ均等に集め、Chrome で生成した PDF と既存の fixture を加えました。 合計 1008 件・3.66 GB、取得失敗はゼロです。

つまずき: 取得の 7 割が失敗した

最初は 8 並列でダウンロードして、40 件中 29 件が HTTP 429 で失敗しました。 逐次に落として 1 件ごとに 0.4 秒空け、429 なら待って再試行する形に変えたところ、 1000 件すべて取得できました。

測る指標

  • 変換成功率 — CLI の終了コード（0 成功 / 3 不正な PDF / 4 未対応・暗号化 / 5 入出力 / 6 時間切れ）
  • 色残り — 出力を 150dpi で描画し、RGB の最大と最小の差が 3 を超える画素を数える
  • 表示崩れ — インクのある位置が動いていないか
  • テキスト保持 — pdftotext の抽出結果が変換前後で一致するか
つまずき: 輝度差で「崩れ」を測ると CMYK 文書が全滅する

最初は変換前後の輝度差で崩れを測りました。ところが CMYK の fixture が 崩れ 0.0206 と出ます。調べると、ずれた画素は輝度 128 → 178 と 明るくなる方向で、最大差は 50 でした。 これは仕様書にある「CMYK は簡易式を使うため ICC 管理より明るくなる」 （シアン 100% は 0.70、poppler は約 0.5 ＝ 255 換算で約 51）と一致します。

色を変えるのが仕事のツールを輝度差で測るのが誤りでした。 インクのある位置（輝度 200 未満の画素）が動いたかで測る方式に作り直し、 さらに増減を分けました。monochrome で薄い色が白に飛ぶのは仕様どおりなので 「消えた」側に、塗り潰しや黒化は「増えた」側に出ます。 崩れとして扱うのは増えた側だけです。これで monochrome の誤検出が 39.7% から 0% になりました。

つまずき: 閾値の際にある明るい色を誤検出した

grayscale で 1 件だけインクが 17% 消えました。調べると彩度 186 の黄緑 （R=167 G=215 B=29）で、仕様の係数で計算すると 167×0.30 + 215×0.59 + 29×0.11 = 180。実測の輝度 180 と完全に一致します。 明るい黄緑が明るいグレーになっただけで、私が決めた閾値 200 のすぐ際にあったのが原因でした。 閾値をまたいだうえで 25 以上動いた画素だけを数えるようにして解消しています。

色残りの 4 件はすべて JPEG 2000（JPXDecode）の未対応警告と対応していました。 仕様書の制限事項どおりで、不具合ではありません。

いま進めていること

1008 件の本番検証を実行中です。当初は grayscale と monochrome を同時に走らせましたが、 6 コアを 6 ワーカーで奪い合って 1 モードあたり約 4 件/分まで落ちたため、 いったん止めて 1 モードずつ流す形に変えました。現在は約 8 件/分で進んでいます。

見落とし: 進捗が見えない作りだった

件数を出す処理は書いていたのに、標準出力がパイプ越しにバッファされて届かず、 結果ファイルも完了時にしか書かれない設計でした。 30 分走らせても「どこまで進んだか」を答えられない状態だったので、 10 件ごとに件数・速度・残り時間を即時出力し、 validation/progress-<mode>.txt にも書くよう直しました。

未対処: 大きすぎる画像が測定から漏れる

検証ログに DecompressionBombWarning が出ています。 画像処理ライブラリが 8,900 万画素を超える画像のデコードを拒否するため、 大判のポスターや地図を 150dpi で描画したページは測定がスキップされます。 何件が影響を受けたかを記録していないのがハーネス側の不備で、 完走後に対処方針を決めます。

実行のしかた

python3 validation/fetch_corpus.py --count 1000
cargo build --release
python3 validation/validate.py --mode grayscale
python3 validation/validate.py --mode monochrome

コーパスと結果は容量が大きいので git 管理外にしています。 手順と指標の詳細は validation/README.md にまとめました。
